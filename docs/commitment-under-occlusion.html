Commitment Under Occlusion

The case for framing the cliff-latch altitude controller as a supervisory commitment mechanism for obstacle avoidance when the obstacle stops being observable mid-maneuver — and for using task-priority control as the baseline it beats, not the alternative it loses to.

Platform ACFR seafloor-imaging AUV Implementation auv_oavoid / oa-mapper Status pre-submission positioning
01

The thesis to write toward

The publishable claim is not “we built a deterministic state machine for AUV altitude control.” Mode-switching avoidance is well-trodden ground, and presented that way the work reads as engineering.

The claim that holds up is narrower and harder to dismiss:

A downward-looking survey AUV cannot observe a cliff top that lies above it, and loses the forward return as it climbs. The tail-clearance constraint nonetheless requires the maneuver to continue for a full standoff plus vehicle length past a feature the vehicle can no longer sense. Avoidance therefore cannot be purely reactive: the controller must carry commitment. Ratcheted, monotone commitment is what makes that memory terminating rather than a source of deadlock.

Everything else in the system — the occupancy grid, the manifold, the mode set — is apparatus supporting that claim. Frame the paper around the observability problem and the apparatus becomes justified design rather than described plumbing.

03

What can be claimed, and what cannot

Determinism is not a contribution — nearly every classical controller is deterministic. Verifiability is, and the method is unusually well placed for it: a small finite mode set, an explicit priority order, and transitions that depend on scalar comparisons.

Claimable, with work

  • Safety. Commanded depth never intersects the manifold plus margin, over a stated terrain class and sensor model.
  • Termination. The latch releases in finite time under forward progress. This follows from monotonicity: the depth target ratchets only shallower, the peak only forward, so release_x is non-decreasing and the vehicle’s along-track position is strictly increasing.
  • No chatter. The hysteresis band on mode selection admits a dwell-time argument.

Not claimable as stated

“The vehicle can never logically enter a stuck control state” is too strong, and the source documents the counterexample. At the latch commit, peak_z - imaging_altitude is deliberately not clamped to zero:

When the obstacle top is above the water surface, the vehicle ascends against the platform’s depth limit and stays there. That is the intended terminal behaviour on a slope too steep to traverse — fail safe at the surface rather than command a depth that takes the vehicle through terrain — and it is the one state the planner does not exit on its own.

Written that way it is a strength: a designed, single, identifiable terminal condition, reached only when the task is infeasible, with escape defined at mission level. Written as an absolute it invites a reviewer to find the exception and distrust the rest.

Name the artifact the claim is about

A correctness property holds of something specific — a model, or the code that flies. The two are not interchangeable, and a paper that leaves the distinction implicit invites the question at review rather than answering it in the text. State the property over the model of §III, establish it there, and say plainly how the implementation is held to it. That link is unusually easy to argue here: the deployed core is a single version-pinned artifact, shared by the vehicle node, the simulator and the log-replay path, so the thing tested is the thing that flies. Model-checking the mode logic (UPPAAL, TLA+, or as a hybrid automaton) is the cheapest credible route to the first half, and is itself a contribution.

04

Task priority: the baseline, not the rival

Reviewers will ask for it, and it should be given to them — as the comparison the method wins, on a problem chosen because it exposes the difference. Null-space-based behavioural control is the canonical marine formulation, and set-based task priority handles inequality constraints of exactly this shape (“maintain at least this altitude”).

The decisive property is that task-priority control is instantaneous. It resolves current task errors through a priority-ordered null-space projection. When the obstacle leaves the sensor field, the obstacle task’s error vanishes, the task deactivates, and the altitude task — next in priority — recovers the vehicle to imaging altitude. Directly into the cliff edge the tail has not yet cleared.

DimensionSupervisory commitment (this work)Set-based task priority
Obstacle leaves sensor view Latch holds; release is position-gated, not observation-gated Task deactivates; lower-priority task recovers

Extension to lateral avoidance Mode set needs redesign Absorbs additional DOF directly
Chatter at boundaries Explicit hysteresis band Activation smoothing; dwell-time analysis needed
Local minima Not applicable — no potential field Known failure mode
Post-dive auditability Mode trace is a discrete, loggable sequence Continuous; harder to explain to an operator

Then close the argument honestly: repairing the task-priority baseline on this problem requires activation hysteresis with dwell time — which is the latch, rediscovered inside a different formalism. That is a far stronger result than “ours is deterministic.” It says the commitment mechanism is necessary, not stylistic, and it makes the state machine the finding rather than the premise.

Concede what task priority genuinely wins. The current system is single-DOF: it commands depth. The moment lateral avoidance is wanted — around rather than over — the mode set must be redesigned where a task-priority scheme would absorb it. Saying so costs nothing and buys credibility for the rest.

05

Proposed structure

Roughly eight pages at conference length; the same skeleton stretches to a journal article by expanding §5 and §6.

  1. I

    Introduction

    Seafloor imaging demands a tight, constant altitude, which puts the vehicle close enough to terrain that cliffs are a collision risk rather than a mapping nuisance. State the observability problem in the first column.

  2. II

    Related work

    Reactive and behavioural avoidance; task-priority and null-space methods in marine robotics; set-based tasks; occupancy and elevation mapping for underwater vehicles. Position against reactivity, not against mapping.

  3. III

    Problem formulation

    Vehicle and sensor model, the observability gap stated formally, the tail-clearance constraint, and the resulting requirement for state. This section is where the paper earns its novelty.

  4. IV

    Representation: the cliff manifold

    Vehicle-relative 2-D grid, upper-envelope extraction, forward extension, and the heading-staleness gate as an explicit model of representation validity under rotation. Report memory and compute — it is a systems result.

  5. V

    Supervisory commitment controller

    Mode set, priority order, the latch with its monotone ratchets, and the release conditions. Present as a hybrid automaton, not as an implementation walkthrough.

  6. VI

    Properties

    Safety and termination, stated over the model of §III and checked. The surface-terminal condition declared explicitly as the single designed exception.

  7. VII

    Experiments

    Baseline comparison in simulation, then replay against field logs, then in-water results. Figure 1’s scenario is the headline case.

  8. VIII

    Limitations and conclusion

    Own the 2-D projection, the single DOF, and the sonar’s missing validity signal. See §7.

06

Evidence: what exists, what is missing

In hand

  • have A validated C++ implementation deployed as an LCM node on the vehicle, with the algorithm core version-pinned to the revision the binary was built from.
  • have Field logs from real deployments, and a playback tool that drives the identical mapper the vehicle runs — the same sensor gating on both paths, so a replay reproduces vehicle behaviour rather than approximating it.
  • have A simulator with procedural terrain and configurable sensor dropout, sharing the deployed core through Python bindings.

Required before submission

  • build The task-priority baseline. Non-negotiable. Implemented against the same logs, through the same replay apparatus, so the comparison is like-for-like.
  • build The formal model and its check. Safety and termination over the §III model.
  • build A cliff scenario the tests actually exercise. The present regression case is degenerate: past the step the vehicle sits below the surface and the height-field caster returns an immediate hit on every beam. It detects change; it does not validate avoidance. A meaningful case needs forward sonar and a caster that resolves terrain above the vehicle.
  • build Quantitative metrics. Minimum clearance distribution, altitude RMS against the imaging target, mode-transition counts, and collision or near-miss counts per transect.

Known gaps to resolve or disclose

  • gap The altimeter no-return test compares range against a configured maximum, standing in for the quality field and zero sentinel the message already carries. On the current vehicle configuration this discards genuine returns beyond 25 m.
  • gap Off-slant DVL beams may fill but not clear voxels, because their 2-D projection misrepresents which voxels they traversed. A real limitation of the projection, worth stating rather than hiding.
  • gap The forward sonar message carries no validity flag at all, so its no-return inference is necessarily heuristic.
07

Limitations to state first

Each of these will be found by a reviewer. Stating them first converts them from weaknesses into evidence of rigour.

  • The map assumes locally straight transects. Collapsing 3-D structure into a vehicle-relative vertical slice is only valid while heading is roughly constant. The 45° staleness gate is an explicit admission of this, and it is honest to present it as a scope condition of the representation rather than a tuning parameter.
  • Single degree of freedom. The controller commands depth. It goes over, never around.
  • Terrain class. Guarantees hold for the terrain the sensors can resolve; overhangs are outside the upper-envelope representation entirely.
  • One terminal state. Slopes too steep to traverse, as in §3.
08

Venue and anchors

With field validation leading, Journal of Field Robotics or IEEE Journal of Oceanic Engineering — both receptive to deployed-system papers with honest post-mortems. With the baseline comparison and formal check landed, IROS or ICRA. A paper resting on the architecture alone will not clear either bar.

Literature anchors to verify and position against

  • Siciliano & Slotine, A general framework for managing multiple tasks in highly redundant robotic systems — the task-priority formulation itself.
  • Antonelli, Arrichiello & Chiaverini, The null-space-based behavioral control for autonomous robotic systems — the marine lineage; the closest framework to compare against.
  • Moe, Antonelli, Teel, Pettersen & Schrimpf, Set-based tasks within the singularity-robust multiple task-priority inverse kinematics framework — inequality constraints and stability; the strongest form of the baseline.
  • Brooks, A robust layered control system for a mobile robot — the behavioural-priority ancestor the reviewer will invoke; address it directly.

Citations above are from recall and must be checked against the actual records before use — titles, authors and years all.
